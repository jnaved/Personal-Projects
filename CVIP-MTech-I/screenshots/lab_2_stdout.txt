[Comprehensive Justification & Technical Answer]:
  Question: Is the file extension alone sufficient to identify the image format?
  Answer  : NO. The file extension is NOT sufficient.

  Technical Justification:
    1. Extensions are Superficial OS Conventions:
       The filename extension (.pgm, .ppm, .bin) is merely an operating system naming convention
       used for shell icon associations. A user or program can freely rename 'image.ppm' to 'image.pgm'
       or 'image.dat' without altering the internal byte structure of the file.
    2. The Header Magic Number is Authoritative Ground Truth:
       Computer Vision algorithms and robust image loaders MUST read the initial bytes (magic number)
       of the file stream. The magic number ('P5', 'P6', 'P2', 'P3') definitively dictates:
         - Whether the raster is Grayscale (1 channel) or Truecolor (3 channels).
         - Whether encoding is raw binary or ASCII text.
         - How many bytes per pixel must be read to prevent memory corruption.

[Technical Explanation: Why the Number of Bytes Changes Despite Constant Dimensions]:
  1. Spatial Resolution vs Radiometric (Intensity) Resolution:
     - The spatial resolution (width x height = 640 x 480 = 307,200 spatial sample points) remains constant.
     - However, the radiometric quantization depth (precision per sample point) is altered.

  2. Information Theory & Bit-Depth Doubling:
     - MaxVal = 255 requires 8 bits (1 byte) to represent 2^8 = 256 discrete gray/color levels.
     - MaxVal = 65535 requires 16 bits (2 bytes) to represent 2^16 = 65,536 discrete intensity levels.
     - Because every individual sample requires twice as many bits of storage, the total raster payload
       DOUBLES exactly (100% increase from 307.2 KB -> 614.4 KB for PGM, and 921.6 KB -> 1.84 MB for PPM).

  3. Color Model Dimensionality Scaling:
     - PPM stores three separate color components (Red, Green, Blue) per pixel.
     - Hence, PPM is always exactly 3x the memory footprint of PGM at equivalent bit depths.
