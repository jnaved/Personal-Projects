================================================================================
          PROBLEM 2 – LOCALLY BALANCED MATRIX ANALYSIS REPORT
================================================================================
Problem Description:
An n x n integer matrix is said to be locally balanced if each element A[i][j] 
is equal to the sum of its valid neighbouring elements in the four directions: 
up, down, left, and right. Only neighbours that exist within matrix boundaries 
are considered.

If the matrix is not balanced, report the first violating element in row-major 
order along with its position (i, j), value A[i][j], and neighbour sum.

--------------------------------------------------------------------------------
1. ALGORITHM DESIGN & PSEUDOCODE
--------------------------------------------------------------------------------
To find the first violating element in row-major order:
- Iterate through rows from row_index = 0 to n-1.
- Iterate through columns from col_index = 0 to n-1.
- For each cell (row_index, col_index):
    1. Initialize neighbour_sum = 0.
    2. Check the 4 adjacent directions: (row_index - 1, col_index), 
       (row_index + 1, col_index), (row_index, col_index - 1), (row_index, col_index + 1).
    3. If a neighbour index falls within [0, n-1], add its value to neighbour_sum.
    4. If A[row_index][col_index] != neighbour_sum, immediately return the 
       position (row_index, col_index), value, and neighbour_sum.
- If all elements satisfy the condition, report that the matrix is balanced.

--------------------------------------------------------------------------------
2. HANDLING OF CORNER, BOUNDARY, AND INTERIOR ELEMENTS
--------------------------------------------------------------------------------
Different cells in an n x n matrix have different numbers of valid neighbours:

a. Corner Elements (4 corners per matrix):
   - Locations: (0, 0), (0, n-1), (n-1, 0), (n-1, n-1).
   - Valid Neighbours: Exactly 2 valid neighbours.
   - Example for A[0][0]: Only Down A[1][0] and Right A[0][1] exist.
   - Check Condition: A[0][0] == A[1][0] + A[0][1].

b. Boundary Elements (Non-corner perimeter elements):
   - Locations: First row, last row, first column, last column (excluding corners).
   - Valid Neighbours: Exactly 3 valid neighbours.
   - Example for A[0][j] (1 <= j <= n-2): Left A[0][j-1], Right A[0][j+1], Down A[1][j].
   - Check Condition: A[0][j] == A[0][j-1] + A[0][j+1] + A[1][j].

c. Interior Elements:
   - Locations: All cells (i, j) where 1 <= i, j <= n-2.
   - Valid Neighbours: Exactly 4 valid neighbours (Up, Down, Left, Right).
   - Check Condition: A[i][j] == A[i-1][j] + A[i+1][j] + A[i][j-1] + A[i][j+1].

Boundary handling is unified seamlessly by validating `0 <= neighbor_row < n` and 
`0 <= neighbor_col < n` before accessing elements.

--------------------------------------------------------------------------------
3. TIME AND AUXILIARY SPACE COMPLEXITY ANALYSIS
--------------------------------------------------------------------------------
Let n = number of rows / columns in the n x n matrix.
Total elements = n^2.

Time Complexity:
- Best-Case Time Complexity: O(1)
  Occurs when the very first element A[0][0] in row-major order violates the 
  locally balanced condition. Checking 2 neighbours takes constant O(1) time.

- Average-Case Time Complexity: O(n^2)
  On average, the algorithm scans a fraction of the n^2 elements before 
  discovering a violation or verifying local balance.

- Worst-Case Time Complexity: O(n^2)
  Occurs when the matrix is completely locally balanced, or when the only 
  violating element is located at the last cell A[n-1][n-1].
  Scanning n^2 cells where each cell evaluates at most 4 neighbours (O(1) work per cell):
  Total Time = n^2 * O(1) = O(n^2).

Auxiliary Space Complexity:
- Auxiliary Space Complexity: O(1)
  The algorithm modifies nothing and allocates no additional data structures 
  or matrices. Only a few primitive scalar variables (indices, neighbour sums) 
  are maintained.
