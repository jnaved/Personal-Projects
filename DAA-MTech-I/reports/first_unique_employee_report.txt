================================================================================
          PROBLEM 3 – FIRST UNIQUE EMPLOYEE ANALYSIS REPORT
================================================================================
Problem Description:
A company records the sequence of n employee names accessing a system. An employee 
is called unique if their name occurs exactly once in the complete sequence.

Design two solutions to find the first unique name:
- Approach 1: Use only the given list and repeated comparisons.
- Approach 2: Use an additional data structure (Hash Map / Frequency Map).

Example Sequence: ["Amit", "Neha", "Amit", "Rahul", "Neha", "Karan", "Rahul"]
First Unique Employee: "Karan"

--------------------------------------------------------------------------------
1. ALGORITHM DESIGN & PSEUDOCODE
--------------------------------------------------------------------------------
Approach 1: List-Only Repeated Comparisons
- Iterate current_index from 0 to n-1.
- For each target_name = employee_sequence[current_index]:
    - Set is_duplicate = False.
    - Iterate scan_index from 0 to n-1:
        - If current_index != scan_index and employee_sequence[scan_index] == target_name:
            - Set is_duplicate = True and break scan loop.
    - If is_duplicate is False, return target_name immediately.
- Return None if no unique name exists.

Approach 2: Hash Map / Frequency Map
- Initialize frequency_map dictionary.
- Pass 1: Iterate through employee_sequence, updating frequency counts:
    frequency_map[name] = frequency_map.get(name, 0) + 1
- Pass 2: Iterate through employee_sequence in original order:
    - If frequency_map[name] == 1, return name immediately.
- Return None if no unique name exists.

--------------------------------------------------------------------------------
2. COMPLEXITY ANALYSIS & COMPARISON MATRIX
--------------------------------------------------------------------------------
Let n = total number of employee names in sequence.
Let k = maximum character length of an employee name string.

+--------------------------+--------------------+--------------------+--------------------+--------------------+
| Approach                 | Best-Case Time     | Average-Case Time  | Worst-Case Time    | Auxiliary Space    |
+--------------------------+--------------------+--------------------+--------------------+--------------------+
| 1. List-Only             | O(n * k)           | O(n^2 * k)         | O(n^2 * k)         | O(1)               |
|    (Repeated Comparisons)|                    |                    |                    |                    |
+--------------------------+--------------------+--------------------+--------------------+--------------------+
| 2. Hash Map              | O(n * k)           | O(n * k)           | O(n * k)           | O(n * k)           |
|    (Additional Data Struct)|                  |                    |                    |                    |
+--------------------------+--------------------+--------------------+--------------------+--------------------+

Detailed Breakdown:

Approach 1 (List-Only Repeated Comparisons):
- Best-Case Time: O(n * k). Occurs when the first element in the sequence is unique. 
  It compares the first element against all n-1 other elements taking n * O(k) work.
- Worst-Case Time: O(n^2 * k). Occurs when no unique element exists or the unique 
  element is at the end of the sequence. Outer loop runs n times, inner loop runs 
  n times, taking n * n * O(k) = O(n^2 * k).
- Auxiliary Space: O(1). Uses zero extra data structures; operates entirely within 
  the input array space.

Approach 2 (Hash Map / Frequency Map):
- Best, Average, & Worst-Case Time: O(n * k). 
  Pass 1 takes n * O(k) to insert/update hash table. 
  Pass 2 takes n * O(k) lookups. Total Time = 2 * n * O(k) = O(n * k).
- Auxiliary Space: O(n * k). Stores up to n distinct name strings of max length k 
  in the dictionary.

--------------------------------------------------------------------------------
3. SUITABILITY FOR LARGE INPUT & SELECTION JUSTIFICATION
--------------------------------------------------------------------------------
- Small Datasets (n <= 100):
  Approach 1 (List-Only) is lightweight, requires zero auxiliary memory allocations, 
  and performs fast in-place comparisons with negligible overhead.

- Large Datasets (n >= 10,000 to 1,000,000+):
  Approach 1 becomes unusable due to quadratic O(n^2 * k) growth. For n = 100,000, 
  Approach 1 requires ~10^10 comparisons (taking minutes/hours), whereas Approach 2 
  requires only ~200,000 hash table lookups (taking milliseconds).

Conclusion:
Approach 2 (Hash Map) is strongly preferred and far superior for real-world and 
large-scale system access logs due to its linear O(n * k) time efficiency.
